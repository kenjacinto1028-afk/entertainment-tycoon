# DATA_INVENTORY — exact JSON ownership and remaining hardcoded values

This document describes every shipped config/JSON file that controls the maintained game. Numeric source values were extracted rather than retuned. **No new economy balancing was performed.** The *authoritative* config consists of the 16 JSON inputs listed below; `compiled.json` is generated by `python tools/build.py`, and the three `*_index.json` files are provenance metadata for the generated tuning keys.

## 1. Authoritative JSON (edit these, rebuild and rerun tests)

Global sector gates are publishing Y1, movies Y4, TV Y7 and games Y10. |

| `config/publishing.json` | Manuscript title pools, publishing/editing formats and treatments, list prices, sales/distribution channels and editorial actions. |

## 3. Retained hardcoded literals — **all file/line positions listed**

The user requested both a numeric/other value inventory and exact locations. They are supplied as machine-readable root TSV files with **source file, line, column, context/scope and literal**:

- **`HARD_CODED_VALUES.tsv`** — 2,444 non-externalized numeric-bearing locations in maintained JavaScript, HTML, CSS, and browser storage, grouped into: 1,850 JavaScript numeric literals **all exactly `0` or `1`** (control, indexing, boolean-like arithmetic), 322 numeric tokens in UI strings or report labels, 3 persistence implementation numeric tokens, 16 HTML presentation numeric tokens, and 253 CSS numeric style tokens. CSV/TSV consumers can filter any path and line. **No other executable JS numeric literal besides 0/1 remains.**
- **`HARD_CODED_STRINGS.tsv`** — 9,107 JS string literal/template-token, HTML attribute and persistence text positions, with source file, line/column, scope, token kind, original length, SHA-256 prefix and escaped preview. Long strings (such as inline SVG or HTML templates) are previewed to 160 characters; full literal is at the **exact listed file/line**. This intentionally includes program protocol keys (`'active'`, `'published'`, role/action identifiers), API command/action names, UI help strings, legal error messages, CSS/SVG markup and user-visible labels. These are not safe to migrate blindly to balance config; their exact values can be part of the save/API contract.

Examples of remaining intentionally hardcoded values (see TSV for *every* occurrence):

| File/line | Literal | Reason still in source |
|---|---|---|
| `src/systems/01_world_calendar_and_setup.js` around line 52 | `0`, `1` in RNG and rounding | Control arithmetic and array truth/false; exported tunable nontrivial constants now in `tuning_engine.json`. |
| `src/systems/16_market.js` in `weekSales()` | `0` and `1`, property keys for genres/distribution | Zero cash, first-index and safety defaults; protocol/property names cannot be removed without save migrations. |
| `src/systems/25_saves.js` in `loadState()` | Status strings and array field names | Schema compatibility and validation; these are program identifiers, not balance data. |
| `src/systems/39_capability_unlocks_and_adviser.js` in `OBJECTIVE_TESTS43` | Real JavaScript predicate logic | Executable checks cannot be serialized into JSON. Their numeric thresholds are in config. |
| `src/interface/17_portraits_and_rights.js` (see TSV 100+ SVG-related entries) | SVG coordinate/path data, text presentation | Portrait/vector geometry and UI output, not game economy; moving blindly would risk rendered graphics. |
| `src/persistence50.js` line 4 (`indexedDB.open(DB,1)`) | `1` IndexedDB schema version | Browser-storage implementation schema, distinct from game save v34. |
| `src/persistence50.js` in `pack()` | `1200000` gzip threshold | Browser-storage infrastructure threshold, not a game balance rate. |
| `src/styles.css` throughout | CSS pixel, rem, color, spacing and breakpoint values | Presentation/layout, not simulation or balance; every numeric location is in the TSV. |
| `src/shell.html` throughout | HTML element and accessibility labels/IDs | UI markup identifiers and presentation; numeric values listed in the TSV. |

**Important distinction:** `HARD_CODED_VALUES.tsv` counts numeric syntax **inside UI strings**, not necessarily standalone numeric rules. `HARD_CODED_STRINGS.tsv` counts many string tokens that are program control/status identifiers rather than tunable “data.” The docs are therefore exhaustive **locators** without claiming all surviving string literals are safe editable config knobs. Any new AI should use the source-context column and type rather than global search/replace.

## 4. Config ownership and validation procedure

1. Edit `config/world.json`, `regions.json`, individual media JSON, `finance.json` or `tuning_*` when needed; no direct edits to `compiled.json` or any generated artifact.
2. Run `python tools/build.py`, then `python tools/verify.py`; optionally `python tools/verify.py --browser` if Playwright is installed.
3. Compare changes with original fixed seed/state hashes in `tests/fixtures/baseline_signatures.json`. Nontrivial changes to balance intentionally change signatures; report the reason instead of suppressing test differences.
4. After any change that affects save schema or calendar/world gates, run native browser and older-save migration tests and update the test report/checkpoint. No game code or balance changes are authorized by this handoff alone.
5. Rebuild the location-based literal inventories if source lines have moved. The delivered TSVs are snapshots of **this exact source**, not self-updating files.
